# Design: Assistant 通用状态源与无变化抑制

### Problem Statement

Assistant 每 5 分钟执行一次，但多轮过程与结果高度接近。需要减少无意义重复，同时在符合契约且已注册的 Source 范围内不漏掉新输入、新异常或待处理事项。

用户进一步明确：**需要的是通用 Harness 架构，不是在调度层写死设备、告警、节能或某类业务规则。**

### Current State

- 当前 scheduled Turn 会重放全部历史正文，没有通用的跨轮状态版本与无变化 skip 判定。
- 工作区已有实时快照、Session Events、Schedule、长期 Memory 与短期上下文，但它们缺少统一的“来源版本”契约。
- 主流 Harness 的 Session、Memory、Checkpoint 能保存历史或状态，但是否需要重复工作仍由执行图或应用条件决定。
- 现有审批/提问在 Agent Loop 内阻塞等待；等待期间 `in_flight` 阻止另一个 scheduled Turn。

### What Makes This Cool

Harness 提供一套通用的“来源是否变化、当前状态是否可用、何时可以安全跳过”的机制。巡检、节能、设备、告警以及未来的新能力都只注册状态源，不需要在调度器里添加专属判断。

无变化时系统安静地留下审计记录；任何来源或工作项版本变化时，当前内容会确定性地进入下一轮输入。

### Constraints

- Harness 不认识设备类型、告警级别、技能阈值或具体业务字段。
- 不新增 Observation 状态机或另一套工作记忆数据库。
- 保留统一 Session Loop、Turn Brief、Skills、审批、Effect、互锁和现有长 Turn 调度语义。
- 保留当前阻塞式审批/提问与 resume，不新增 waiting-partial 生命周期。
- 最终回复继续使用普通 Markdown；执行事实由 Session Events 承载。
- 来源不可用、状态损坏或覆盖不完整时必须完整执行，不能静默跳过。
- 不通过文本去重掩盖重复执行；后端先生成真实变化与结果，前端只做投影。

### Premises

1. Harness 的通用职责是状态版本、preflight、执行与审计，不是业务状态判断。
2. 每个来源最了解自己的语义，数值抖动、内容规范化、活跃/等待/关闭等业务判断必须留在来源适配器。
3. 历史、长期记忆和 Checkpoint 不能替代“本轮有什么变化”的输入契约。
4. 只保存 pre-turn 完整来源状态，不使用 post-turn 状态推断模型覆盖。
5. 首版 skip 依据完整语义快照；任何完整 Turn 都保留全 Source 输入，不做增量覆盖推断。

### Approaches Considered

### Approach A：提示词与历史裁剪

只带上轮摘要并要求无变化简短回复。无法从机制上减少重复工具执行，也不保证变化判断可靠。

### Approach B：业务字段差分

在 Harness 中直接比较设备、告警、技能和审批字段。首版直观，但新增业务会持续修改核心调度，不符合通用架构要求。

### Approach C：通用 Source + Revision + WorkItem（选定）

Harness 只处理通用来源版本、工作项版本、控制输入和审计。业务来源负责提供完整状态与语义变化，新增能力不需要修改调度核心。

### Approach D：薄指纹门 + 原有完整 Turn（首版采用）

Source 仍提供 revision/stateHash 与 WorkItem 语义快照，但变化后继续走现有完整输入。它以最小改动验证大部分 skip 收益，并避免把增量上下文正确性与 skip 同时上线。

### Approach E：事件驱动唤醒（后续方向）

Source revision 变化可直接触发唤醒，定时调度只负责对账，可能进一步降低延迟与成本；首版只保留同一 revision 契约的扩展能力，不实现事件驱动。

### Approach F：只降低调度频率

实现最薄，但无法区分有价值变化与重复工作，还会增加异常延迟；可作为工作区现有配置，不替代通用 skip 门。

### Delivery Decision

主审发现“无变化 skip”与“增量提示词、覆盖确认、物理回收”不应一次上线。当前计划采用分阶段交付，保留通用 Source + Revision + WorkItem 方向，但缩小首版实现：

| 阶段 | 行为 | 是否当前实施 |
|---|---|---|
| Phase 0：shadow | 现有 Turn 完整执行不变，额外计算 `wouldSkip`、各 Source veto、变化率与预计节省 | 是 |
| Phase 1：安全 skip 门 | 无变化时零模型/工具调用；有变化时保留现有完整历史与全 Source 输入语义 | 是 |
| Phase 2：增量输入与回收 | analyzedWork、requiredAcks、增量提示词、物理 tombstone 释放 | 否，独立评估与批准后另建设计 |

Phase 1 不实现 Phase 2 的覆盖确认或释放状态机。WorkItem 仍是 Source 完整语义快照的一部分；skip 只比较完整语义 revision/stateHash，因此首版不需要逐项证明“已进入模型”。

上线证据分为 shadow 估计与 canary 实测。shadow 至少覆盖 3 个代表性工作日和 100 个 scheduled Turn，`wouldSkip` 比例 ≥50%；估计模型节省为 `wouldSkip=true 的实际模型调用数 / 全部 shadow 模型调用数`，估计工具节省为 `wouldSkip=true 的模型驱动工具调用数 / 全部 shadow 工具调用数`，均明确标记 counterfactual estimate，不能声称 shadow 已节省。

通过 shadow 后，只在指定 canary workspace 短期启用 enforce，收集至少 20 个实际 Turn。实际模型与工具调用下降 ≥40%、人工标注的用户可见重复报告下降 ≥80%、preflight 额外延迟 p95 ≤250ms，并且全部 wouldSkip 样本经“语义输入是否已变化”的人工复核无错误 skip，才允许长期 enforce。canary 同时验证真实节省与重复报告，而不是用不同措辞推断 false skip。

`suppression_gate_evaluations` 持久化不可变 gate artifact：artifactId、workspace、样本 turn IDs/日期、各分母、shadow estimated、canary measured、false-skip 复核人与结论、延迟分布、审批人和 SHA-256。PUT enforce 必须校验最新已批准 artifact；没有 artifact、审批人或 canary 实测时只能 off/shadow。未达标不启动 Phase 2。上述数值是暂定上线 Taste 决策，在最终批准门单独呈现。

### Recommended Approach

### 1. 通用状态源契约

每个可影响 Assistant 执行的内容提供一个小型 Source Adapter：

```text
SourceSnapshot {
  sourceId,
  sourceVersion,
  revision,          // 不透明 UTF-8 字符串，1..=256 字节
  stateHash,         // "sha256:" + 64 个小写 hex，覆盖完整规范语义投影
  available,
  empty,
  stateRef,          // 可确定解析完整当前语义投影
  workItems: [...],  // 当前完整语义工作项投影
  error              // unavailable 时的 SuppressionError；available=true 时为 null
}

WorkItem {
  workKey,              // 与 sourceId 组成全局身份
  revision,          // 不透明 UTF-8 字符串，1..=256 字节
  disposition,       // active | waiting | closed
  payloadRef,        // Adapter 命名空间内的不可变引用，不含秘密
  payloadHash        // "sha256:" + 64 个小写 hex，对应 payload 规范字节
}
```

- `sourceVersion` 是 adapter/schema 的无符号整数版本，版本不兼容时不能比较并跳过；`turn.state.stateVersion=1` 是 Harness envelope 版本。`registryVersion` 为排序后 `(sourceId, sourceVersion, stateVersion)` 列表的 SHA-256。
- `revision` 是不透明 UTF-8 字符串，1..=256 字节，不要求 Harness 理解其格式；`stateHash/payloadHash` 为 `sha256:` 前缀加 64 个小写 hex。
- 规范语义字节由唯一 `canonical.rs` 生成：UTF-8 NFC、LF、无多余空白、对象键按 JCS/RFC 8785 的 UTF-16 码元排序；重复对象键、NaN/Infinity、非有限数拒绝，-0 归一为 0，数字使用 JCS 最短往返表示，Unicode 转义与 UTF-8 输出唯一。普通数组顺序有语义，WorkItem 按 `(workKey, revision)` 排序，重复 `(sourceId, workKey)` 拒绝；其他无序集合由 Adapter 先规范化排序。
- 哈希使用 domain separation：`tinyiothub:source-state:v1\0`、`tinyiothub:work-payload:v1\0`、`tinyiothub:source-registry:v1\0` 前缀后接规范字节。共享 golden vectors 与 property tests 覆盖数字、-0、非有限数、Unicode、重复键、数组和 domain 分隔。
- `available=false` 时 `empty=false`、`stateRef=null`、`workItems=[]` 且 `error` 为安全 SuppressionError；`available=true, empty=true` 必须有合法 stateRef、空工作项哈希且 `error=null`。available=true 时所有 refs/payloadHash 必填。Registry 拒绝重复 sourceId 以及 descriptor 与 snapshot 的 sourceId/sourceVersion 不一致。
- `stateRef` 与 `payloadRef` 必须指向捕获 revision/stateHash 对应的不可变内容，后端解析时重新校验版本与哈希；若内容已变化则重建整个快照或失败回退，不能将旧 revision 标记到新内容上。
- 工作项身份固定为 `(sourceId, workKey)`，在比较、持久化、模型覆盖与测试中使用同一复合键，禁止不同来源共享覆盖。
- 所有 Source 都必须把语义投影与采集/存储元数据分离。`revision/stateHash` 的规范化输入包含 active/waiting/closed 工作项的语义内容、revision 和 payloadHash；纯采集时间、存储位置与保留标记不参与哈希。
- 来源必须为刚关闭的工作项保留含当前 payload 的 closed tombstone。工作项被直接删除或从数据源消失时，同样必须生成带新 revision 的 closed tombstone，并保留最后可确认的当前 payload；若连该 payload 也无法取得，则来源必须 `available=false` 或报告契约冲突，不能伪装成健康空集合。
- Phase 1 的 closed tombstone 至少保留到包含该 closed revision 的首个成功完整 scheduled Turn 完成；之后沿用 Source 现有保留策略，任何语义清理都改变 revision/stateHash。首版不新增物理回收、覆盖确认或释放协议；每次完整执行都注入当前完整语义快照，因此不需要 analyzedWork/requiredAcks 来证明增量覆盖。
- 来源完整状态仍由 Source Adapter 保存或可通过 `stateRef` 重建；Harness 只保存通用 envelope 和持久引用，不复制业务 payload。
- 新设备类型、新技能或新告警规则只需让对应来源产生正确 revision，不修改 Harness。

### 2. 来源负责语义，Harness 负责版本

Source Adapter 必须保证：

- 任何会改变模型判断的内容、配置、答案或状态变化都改变相应 revision；
- 普通数值抖动、纯时间戳前进或无关采集噪声不会改变 revision；
- 活跃、等待、关闭与内容更新按自身语义映射为通用 WorkItem disposition/revision；直接删除或消失也必须映射为带最后 payload 的 closed tombstone；
- 状态不可用时 `available=false`，不能把缓存或读取失败伪装为未变化；
- `stateRef` 能重建当前完整状态，`payloadRef` 能重建当前工作项内容与答案；
- 相同 revision 但 stateHash 不同属于来源契约冲突，必须完整执行并报告。

因此，告警阈值、设备离散状态、技能版本、工作区指令、短期内容和唤醒文本的语义都留在各自 adapter，不进入 Harness 核心。

### 3. 通用 Turn 基线

新增仅后端可读的 `turn.state`；公共 Session Events API/SSE 必须在服务端过滤该事件，不能只依赖前端默认忽略。

```text
turn.state {
  stateId,
  stateVersion,
  turnId,
  observedAt,
  sources: [{ sourceId, sourceVersion, revision, stateHash,
              available, empty, stateRef, workItems, error }],
  controlCursor,
  registryVersion,
  mode
}
```

- 这是本轮开始前、用于本次执行的完整通用来源快照。
- `controlCursor` 首版只覆盖 `session_events` 中 `event_type=message.created` 且 `payload.role=user` 的事件，记录最近成功完整 scheduled Turn 的完整输入所包含的最高 session 事件 seq；执行期间新到的消息不推进。失败、取消、partial 或上下文拒绝不推进基线或 cursor。它只用于 preflight 新输入判断，不用于裁剪完整 Turn 的既有历史。
- `registryVersion` 标识当前 Source 注册表及 adapter/schema 集合；注册或版本变化使旧基线失效。`mode=shadow` 只记录判定，`mode=canary` 用于限定工作区实测，`mode=enforce` 才允许长期 skip。
- 用户消息继续由现有不可变 Session Events 与完整历史输入保留；首版不新增“序列化后即可清理”的捷径，也不把用户消息包装为 Source/WorkItem payload。
- 不保存 post-turn 基线。本轮产生的来源或工作项变化将在下一轮与本轮 pre-turn envelope 比较，不会被误标为已覆盖。
- 只有所有 Source available、引用完整且成功完成的 scheduled Turn 才提供基线；degraded、失败、取消、partial、损坏、缺失或 registryVersion 不兼容强制下一轮完整执行。默认每 1800 秒至少强制执行一次 reconciliation，忽略 skip 判定并注入所有已注册 Source 的当前完整状态，为 Adapter 漏报设置时间上限。
- skip 不推进基线；event/chat Turn 不推进 scheduled 基线。
- 当前阻塞式审批/提问继续由 `in_flight` 防止等待期间的新 scheduled Turn，不引入 waiting-partial 分支。

持久化 `suppression_state`（workspace DB、每 session 一行）保存 baseline envelope、`controlCursor`、registryVersion、configVersion、stateVersion、最近 full attempt、`full_attempt_in_progress`、`full_failed`、`audit_in_progress`、`schedule_sync_pending`、`projection_sync_pending` 与 `notification_pending`。`turn.state` 是该行的不可变事件投影，不是唯一恢复依据。

生命周期必须按以下事务边界执行：

1. 任何完整 scheduled/reconcile Turn 开始前，以 CAS 写入 `full_attempt_in_progress` 并递增 attemptNo，使旧 baseline 立即不可选；崩溃留下的该 fence 禁止后续 skip。
2. 只有所有 Source available、引用完整的成功完整 Turn，才在一个事务中写入新 baseline、controlCursor、turn.state 并清除 full fence。degraded、失败、取消、partial、context rejected 或超时写 `full_failed`，旧 baseline 直到下一次成功完整 Turn 前保持不可选。
3. skip 先以 CAS 写 `audit_in_progress`；原子审计事务重验状态并同时写入 skipped 事件及 schedule/projection/notification pending。审计失败尽量写 `audit_failed`，若连该写入也失败，已存在的 `audit_in_progress` 仍禁止后续 skip。
4. Schedule、Session 投影和 SSE 成功后分别清除 pending；失败保留 shared durable fence。任何 worker 的 preflight 和 skip 提交都检查这些字段，进程内 suppression-disabled 仅是额外保护，不是唯一屏障。
5. 重启恢复先读取 full/audit/pending fence 与事件 IDs，决定重放、对账或完整执行；不能用 post-turn Source 状态推断覆盖。手动 reconcile 与 scheduled 使用同一生命周期。

### 4. 是否允许无变化 skip

只有同时满足以下条件才允许 skip：

1. workspace 开关为 canary 或 enforce，registryVersion 与基线一致，所有已注册 Source available，sourceVersion 与 schema 兼容；首版没有可豁免的可选来源；
2. 每个 Source 的 revision 与 stateHash 相对基线均无变化，完整 stateRef/payloadRef 可解析且校验通过；
3. 当前没有 `seq > controlCursor` 的新用户输入；
4. 当前未到 reconciliationSeconds 指定的 reconciliation 时间，没有基线损坏、来源覆盖缺口或契约冲突。

shadow 模式使用同一条件计算 `wouldSkip`，但始终继续现有完整 Turn。任一 canary/enforce 条件不满足则完整执行。关闭、删除或消失的工作项都以带新 revision 和最后 payload 的 closed tombstone 改变 Source 快照并进入下一轮完整输入；waiting 项内容不变时不会制造重复模型调用。保证仅限于“符合契约且已注册的 Source”，不宣称能发现未注册来源或 Adapter 错删语义；后者由符合性测试、真实样本和周期 reconciliation 缓解。

### 5. 完整执行输入

Phase 1 的每次完整执行都保留现有提示词与历史语义，输入包含：

- 所有已注册 Source 的完整当前语义内容，而不是只注入 revision 变化的 Source；
- 所有 active/waiting/closed WorkItem 的当前 payload，包括直接删除后保留的最后 payload；
- 现有完整会话历史与当前用户消息、最近结论和当前唤醒输入；
- 可选的通用 revision 变化元数据，仅作附加解释，不替换任何原有上下文。

无基线、基线失效、reconciliation 或 shadow 模式使用同一完整输入规则。长期 Memory、Turn Brief、Skills 和 SHORT_TERM.md 每次完整执行都重新加载当前实际注入版本，不因 revision 未变而从上下文中省略。首版不读取其他 session，不做自由文本相关性筛选。

构造请求时必须按捕获 revision 解析不可变引用并校验哈希；版本错配时重建整个快照，仍失败则给出可见错误且不推进基线/controlCursor。provider 上下文预算按完整请求计算，包含 system/developer prompt、工具 schema、全部消息与 Source payload、编码开销和输出预留；超出返回 `context_too_large`，窗口或计数方式未知返回 `context_budget_unavailable`。两者均不静默截断、不推进基线/cursor，并保留全部待处理内容。

容量恢复属于上线门槛：用接近真实最大开放工作量的负载测试验证可恢复性。runbook 必须给出人工恢复路径，包括处理积压工作项、保留未覆盖输入并切换到已批准且容量足够的 provider；未经独立批准不得引入摘要或分块。持续超窗必须告警，不能把永久报错当作完成。

不可用来源也必须以降级输入进入完整 Turn：`sourceId`、`available=false`、安全错误标记与已知水位。它不能被静默省略成健康空集合；无法构造完整输入时本轮失败并保持下一轮完整执行。

### 6. 原子 skip 审计与失败屏障

无变化 skip 的完整现有生命周期在** workspace 数据库的一个 SQLite 事务**中提交：

```text
trigger.received → wake.dispatched → session.started
→ turn.started(turnKind=scheduled)
→ turn.completed(outcome=skipped, reason=no_material_change,
                 baselineStateId, checkedAt)
→ session.ended(skipped)
```

- 沿用现有事件 ID 与关联字段；完整事件序列必须原子提交，SSE 只在事务提交成功后通知。`wakeId` 由 `(workspaceId, plannedWakeAt)` 稳定派生；每次 attempt 从 suppression_state 分配单调 attemptNo，turnId/wakeEventId/event IDs 由 `(wakeId, attemptNo)` 派生。已提交 skip 永不覆盖，状态变化后的完整 Turn 使用新 attempt 并以 `previousAttemptId/supersedes` 关联同一 wake。
- skip 提交事务必须同时满足：当前为 canary 或 enforce、configVersion 与 preflight 相同、registryVersion 不变、没有 `seq > controlCursor` 的用户事件、除当前 audit_in_progress 外没有其他 full/audit/sync fence、stateVersion 未变化。PUT off 在返回前提交 mode=off 并递增 configVersion，因此不得出现 off 返回后才可见的旧 skip。外部 Source 以 observedAt 快照为边界，之后的变化在下一轮完整执行。
- 未变化且结果已知的重放返回已提交 skip，不新增事件；Schedule/projection/notification 尚未对账时只恢复对账，不创建新 Turn。
- 平台库的 Session 状态是独立投影，不与 workspace 事件处于同一事务。它只能在事件提交后更新或由后续读取/重试对账；前端 skip 展示只依赖已提交的 workspace 事件，不把 Session 投影更新失败伪装成事件回滚，也不宣称存在跨库原子事务。
- skip 提交后的 SSE 通知失败不得回滚已提交事实。服务端记录 `notification_failed`、workspace/turn/event IDs 与 traceId，report 暴露通知降级；客户端从 high watermark 重连重放，服务端不向已断客户端无限重试。持续通知失败进入告警，恢复后必须核对投影而不重复生成 Turn。
- Schedule 失败屏障写入失败表示“skip 已提交、Schedule 未确认”的 committed/partial 状态：进程禁止后续 skip，操作员先按 plannedWakeAt 查询审计，再以总尝试最多 3 次（首次+2 次重试，1/2 秒退避）恢复；未知结果必须先对账，禁止盲目重放。
- 前端只从完整提交的 skipped 终态显示“本轮无显著变化”，不生成重复长报告。
- 任一事件写入失败则全部回滚，不出现可见 skipped 终态。
- 失败结果由 TriggerRouter 唯一持久化：WakeRunner 返回明确的 `WakeOutcome::AuditFailed`，Router 的既有 `mark_assistant_wake` 将 `last_outcome=audit_failed` 写入 Schedule。不得再由后续通用 skipped/failed 覆盖；基线选择据此强制下一轮完整执行。
- 当前进程同时设置 session 级 suppression-disabled，直到下一次完整成功 Turn 后清除。
- 进程启动后，尚未在本进程完成过完整 Turn 的 session 默认先完整执行一次，避免重启后直接 skip。
- 如果连失败屏障也无法持久化，当前进程仍禁止 skip，不宣称审计成功。

### 7. Session Events 的自反馈排除

Session Events Adapter 不能把 Harness 自身活动当成新的业务输入：

- `turn.state`、trigger/wake/session/turn 生命周期、skip 审计、step 输出和当前 Assistant 的结论不改变待处理 revision；否则每次 skip 都会触发下一次执行。
- 首版游标控制流只包含 `message.created(role=user)`；这些事件按 session 事件 ID/seq 从 Session Events Adapter 的语义工作项中排除，只通过 controlCursor 参与新输入判断。assistant 报告不能再次成为新工作，其他事件类型不得被隐式归入 controlCursor。
- 已由其他 Source Adapter 表示的设备、审批、提问、Todo 和短期事项不得在 Session Events Adapter 中重复计入。
- 其他尚未覆盖的外部语义事件以稳定事件 ID、类型和规范化语义载荷形成版本；只有成功完整 Turn 覆盖后才不再作为新事件触发。
- 必须用真实 Session Events Adapter 验证连续至少两轮 skip，同时证明新的外部语义事件仍会触发完整执行并进入模型输入。

### 8. 记忆边界

- 长期 Memory：偏好、持久事实、已验证经验和关键决策。注册为普通 Source Adapter，其 revision 覆盖当前实际注入的记忆集合；memory-only 变化触发完整执行，每次完整执行重新加载当前内容。
- `SHORT_TERM.md`：仍需关注的短期内容，作为一个普通 Source Adapter 提供 revision 与内容引用。
- `turn.state`：本轮开始时的通用来源与工作项版本，不进入长期语义记忆。
- 周期报告不自动沉淀为长期记忆，避免重复反射放大相同内容。

#### 9. Phase 1 保留、现实校验与上线屏障

- closed tombstone 沿用 Source 现有保留策略，原始 Session Events 不可变保留；首版不物理释放 tombstone，不新增 analyzedWork、requiredAcks、ineligible/eligible、ack_failed 或 release_failed。
- 每个 Adapter 必须通过统一语义符合性测试和真实样本回归：任何影响模型判断的新增字段、答案、直接删除或状态变化都改变 revision/stateHash；噪声不改变。未注册来源和 Adapter 错删语义不在绝对保证范围内，必须显式记录该边界。
- 默认每 1800 秒 reconciliation 强制完整执行；Source 注册表或 adapter/schema 版本变化立即使旧基线失效。上线初期持续比较完整执行与 shadow 判定，发现错误 skip 立即关闭 enforce。
- workspace 级 `off | shadow | canary | enforce` 开关默认 off。off 完全保持现状；shadow 只观测；canary 仅在已批准 shadow artifact 的指定 workspace 实测 skip；enforce 需要包含 canary 实测的最终 artifact。kill switch 将开关设为 off，立即恢复完整执行，无需回滚数据。首版不提供 Source quarantine 或单 Source 豁免，整个 workspace 的 off 是唯一安全逃生门。
- workspace `reconciliationSeconds` 默认 1800，允许 300..=86400；runtime `recoveryMaxAttempts=3`（允许 1..=3，含首次调用）与 `alertAfterConsecutiveFailures=3`（1..=20）均有类型和范围校验。临时恢复最多 3 次总尝试，即首次加最多 2 次重试，退避 1/2 秒。shadow 阈值只能在 off/shadow 下修改，enforce 时修改须先转 off；非法值拒绝且不写部分配置。
- shadow/canary 指标至少包含 `wouldSkip`、实际 skip、各 Source veto 分布、连续 skip 长度、不可用导致的完整执行、reconciliation 次数、模型/工具调用变化和 preflight 延迟，并显式标记 estimated 或 measured。低收益、高噪声或 Adapter 不可用持续发生时保持 off/shadow 并告警，而不是扩展协议。
- Source Adapter 必须批量加载工作项，禁止逐 WorkItem SQL；controlCursor 与基线查询复用 `idx_session_events_mode_session_seq`。turn.state 只存 envelope/ref，不复制完整 payload；10x/100x workspace 负载测试记录快照捕获、历史 reseed、skip 提交的 p95/p99、内存与 DB 占用，超预算时背压/告警而非新增固定配额。
- 历史清理沿用现有策略，不新增固定事件配额，也不以“已序列化”为由提前清理用户输入。

### 10. Source Author 契约与命名

Rust/JSON 契约固定如下，所有 JSON 使用 camelCase；Rust 内部使用 snake_case，事件名使用点分隔小写，稳定错误码使用 snake_case：

```rust
pub const TURN_STATE_VERSION: u32 = 1;

pub struct SourceDescriptor { pub source_id: String, pub source_version: u32 }
pub struct StateRef { pub id: String, pub revision: String, pub state_hash: String }
pub struct PayloadRef { pub id: String, pub revision: String, pub payload_hash: String }

#[async_trait]
pub trait AssistantSource: Send + Sync {
    fn descriptor(&self) -> SourceDescriptor; // sourceId + sourceVersion
    async fn capture(&self, cx: &SourceContext)
        -> Result<SourceSnapshot, SourceError>;
    async fn resolve_state(&self, reference: &StateRef)
        -> Result<CanonicalBytes, SourceError>;
    async fn resolve_payload(&self, reference: &PayloadRef)
        -> Result<CanonicalBytes, SourceError>;
}

// Harness 只调用 registry；每个 adapter 在一次 capture 中批量取得 WorkItems。
// refs 是 adapter 命名空间内的 opaque ID，不是允许 Harness 任意抓取的 URL。
```

`SourceContext` 只含 workspaceId、sessionId、observedAt 与 mode，不含 provider credential。`SourceDescriptor`、`SourceSnapshot`、`WorkItem`、`StateRef`、`PayloadRef` 所有字段均为 required，只有 unavailable 时 `stateRef=null` 且 workItems 为空。`CanonicalBytes` 是共享的已验证规范字节 newtype（含 revision/hash），不是 Adapter 私有返回类型；业务 payload 内容本身仍只由 Adapter 解释。哈希计算使用增量 writer，避免为哈希再复制一份完整字节。

`docs/dev/assistant-suppression.md` 必须包含两个完整可编译示例：StaticSource 重复 capture 返回相同 revision/hash；ChangingSource 先修改工作项再回答/关闭它。共享 `assert_source_contract` 测试入口覆盖 nil、合法 empty、噪声、关闭、直接删除、payload 缺失、引用错配、重复 workKey、revision/hash 冲突和 registry 变化。

稳定 `SkipVeto` JSON 值为 `disabled`、`baseline_missing`、`baseline_corrupt`、`source_unavailable`、`source_changed`、`source_ref_mismatch`、`source_revision_conflict`、`registry_changed`、`new_user_input`、`reconciliation_due`、`audit_failed`。其中 baseline_missing、registry_changed 和 reconciliation_due 是正常完整执行原因，不作为错误告警。

### 11. Agent-ready 错误与恢复契约

所有新错误使用 typed `SuppressionError`，包含 `code/what/fix/recovery/codeAnchor/context/trace/redaction/channel`。`codeAnchor` 指向 `docs/dev/assistant-suppression.md#errors` 的具体锚点；HTTP 新路径使用对应状态的 `application/problem+json`，异步路径写入 `turn.completed(outcome=failed).error`，同时保留前端现有 `errorMessage` 安全摘要，告警进入 tracing、HUD lastOutcome 与 suppression report。

```json
{
  "code": "context_too_large",
  "what": "assemble scheduled Turn: measured input + output reserve + overhead exceeds provider window",
  "fix": "Reduce registered backlog or select an approved larger-context provider, then reconcile",
  "recovery": {
    "action": "fix_then_reconcile",
    "maxAttempts": 3,
    "sideEffects": "none",
    "baselineAdvanced": false,
    "reconcile": "required_after_unknown_outcome"
  },
  "codeAnchor": "docs/dev/assistant-suppression.md#context_too_large",
  "context": {
    "workspaceId": "...",
    "turnId": "...",
    "provider": "...",
    "model": "...",
    "contextWindow": "known integer",
    "countedInputTokens": "known integer or null",
    "outputReserveTokens": "known integer or null",
    "countingMethod": "provider tokenizer/version or unavailable"
  },
  "trace": { "traceId": "correlation UUID", "localPath": "local-only trace path or null" },
  "redaction": "payloads, memory contents, ref internals and credentials omitted",
  "channel": "turn.completed + suppression report"
}
```

context 只能包含 allowlist：workspace/session/turn/plannedWake/event IDs、sourceId、sourceVersion/stateVersion/registryVersion、expected/actual hash、provider/model、预算数值、计数方法、mode、veto、operation 与 caller-safe cause。workKey/revision 只允许出现在后端日志且必须 telemetry-safe，公共 problem response 不得包含。远程只返回 traceId；localPath 仅本地可见。payload、Memory/Skill 正文、设备秘密、provider credential、Authorization、数据库路径中的用户目录和任意 URL 查询串不得进入错误。

| code | fix 与恢复 | sideEffects / channel |
|---|---|---|
| `source_unavailable` / `source_missing` | GET preflight/report 定位 Source；修复后 POST reconcile；连续 3 次失败告警，禁止 skip | preflight none；完整 Turn 按既有语义 / event + report |
| `work_item_payload_missing` | 恢复 closed tombstone 后完整执行；无法恢复则 workspace off，禁止健康空集合 | none / event + report |
| `source_revision_conflict` | 运行 Source conformance，修正 revision 生成后 reconcile | none / event + alert |
| `source_ref_mismatch` | 重建快照一次；仍失败则恢复不可变 ref 后 reconcile，不推进基线 | none / event + report |
| `baseline_corrupt` | 丢弃基线并完整执行；持续损坏先 off 再修存储 | baseline discarded / event + report |
| `input_build_failed` | 查看 traceId，修复输入后完整执行；无法构建则 off | none / event + local trace |
| `context_too_large` | 减少注册积压或选择已批准更大窗口 provider，随后 reconcile；不得截断 | none / typed event + alert |
| `context_budget_unavailable` | 配置 provider 真实窗口和 tokenizer/计数版本，随后 reconcile；不得猜测 | none / typed event + report |
| `audit_write_failed` | 修复 workspace DB；按 plannedWakeAt 查询事件，总尝试最多 3 次（首次+2 次重试，1/2 秒退避） | rolled_back / schedule `audit_failed` |
| `schedule_barrier_failed` | 已提交 skip 先对账，再恢复 Schedule；未知结果不得盲目重放 | committed_partial / report + local trace |
| `projection_reconcile_failed` | 读取已提交事件并对账，最多 3 次；持续失败告警且禁止后续 skip | committed / report + alert |
| `notification_failed` | 客户端按 high watermark 重连重放；服务端不无限重试，持续失败告警 | committed / report + tracing |
| `false_skip_detected` | 立即 PUT suppressionMode=off，再 POST reconcile 并核对 baseline/current snapshot | unknown until reconciled / alert + local trace |
| `shadow_gate_not_met` | 保持 shadow，检查 gate metrics；不得强行 enforce | none / HTTP 409 problem |
| `suppression_config_invalid` | 修正字段和范围后重试 PUT；原配置不变，off 不带其他字段始终可用 | none / HTTP 400 problem |
| `wake_in_flight` | 读取当前 Turn，完成后使用同一 Idempotency-Key 重试；不得并发唤醒 | existing wake only / HTTP 409 problem |
| `idempotency_conflict` | 同 key 不同 operation/fingerprint 时改用新 key；不得重用为不同意图 | none / HTTP 409 problem |
| `preflight_timeout` | 检查慢 Source，恢复后完整执行；超时不推进 baseline，持续发生告警 | none / event + report |
| `wake_backpressure` | 按 retryAfterMs 使用同一 Idempotency-Key 重试，不新增排队请求 | none / HTTP 429 problem |

临时 DB 恢复总尝试最多 3 次（首次+2 次重试，1/2 秒退避）；永久性配置/契约错误不自动重试。任何 unknown outcome 先按 event IDs 对账。`valid_empty`、`baseline_missing`、`registry_changed`、`reconciliation_due` 和幂等重复 wake 不发送错误。

告警使用 `assistant.suppression.alert`（Session Events Adapter 排除此类 Harness 自反馈）+ tracing + HUD/report，不新增外部通知渠道。payload 包含 code、workspaceId、turnId、baselineStateId、当前/基线 registryVersion、vetoes、连续失败数、相关指标和 traceId。错误 skip 必须立即 off 并执行一次强制完整 reconciliation；重新 enforce 需要根因修复、连续两次正常 preflight 和既有 shadow gate 仍满足。

### 12. 可执行 API、quickstart 与 TTHW

| API | 行为 | 权限与错误通道 |
|---|---|---|
| `PUT /api/v1/workspaces/{id}/agent/schedule` | 扩展 `suppressionMode`、`reconciliationSeconds`；off 立即可用，canary 校验 shadow artifact，enforce 校验 canary 实测 artifact | workspace write；新校验错误 RFC 9457 |
| `GET /api/v1/workspaces/{id}/agent/suppression/preflight` | 只读返回 decision、wouldSkip、vetoes、registryVersion 与 refs 状态，不推进任何状态 | workspace read；预期 veto 返回 200，意外错误 problem |
| `GET /api/v1/workspaces/{id}/agent/suppression/report` | 返回公开投影（非原始 turn.state）、指标、最近 outcomes、alert/notification 状态；不返回 payload 或秘密 | workspace read；意外错误 problem |
| `POST /api/v1/workspaces/{id}/agent/suppression/wake` | 按当前 mode 执行一次正常 scheduled wake，可能完整执行或 skip | workspace write + Idempotency-Key；202/409 + 异步 typed event |
| `POST /api/v1/workspaces/{id}/agent/suppression/reconcile` | 强制完整 Turn，忽略 wouldSkip，保留 pre-turn 证据 | workspace write + Idempotency-Key；202/409 + 异步 typed event |

原始 `turn.state` envelope（stateRef/payloadRef/workKey/revision）只保存在后端并用于 preflight，不进入公共 Session Events API/SSE。preflight/report 使用独立 Public DTO，只含 sourceId、sourceVersion 兼容性、available/empty、active/waiting/closed 数量、veto、refValidation 状态、安全错误码和 registryVersion；不包含 refs、workKey、revision、payload 或用户文本。ID 必须由服务端生成或经脱敏，problem response 同样禁止内部存储路径和用户派生 workKey。

新端点复用 tenant/workspace 访问校验；写操作还必须使用现有 workspace write 权限，不得仅凭 tenant ID。202 只返回 sessionKey、turnId、`outcome=accepted` 与 report URL，最终 modelCalls/toolCalls 仅在 report 的终态记录中出现，202 中不得伪造或提前填写。

`suppression_idempotency` 持久化 workspace、operation（wake|reconcile）、key、requestFingerprint、plannedWakeAt、attemptId 与结果。唯一键为 `(workspaceId, operation, key)`：相同 HTTP 请求返回已记录结果，即使 Source 已变化也不得把它当成新意图；同 key 不同 operation 或 fingerprint 返回 409 `idempotency_conflict`，新意图必须使用新 key。并发相同请求由数据库唯一约束选出一个 winner，其余请求读取同一结果。终态未知时先按 attempt/event IDs 对账，不得直接重试。调度器崩溃重放不是普通 HTTP 重试：只有 Source/用户状态未变化才返回旧 skip，变化后按新 attempt 完整执行。

`docs/dev/assistant-suppression.md` 提供完整 quickstart，`apps/cloud/examples/suppression_quickstart.rs` 只在 loopback 启动 synthetic fixture：内存 SQLite、StaticSource、ChangingSource、固定 `ws-suppression-demo` 和合成 `test-token`，不连接真实 provider、设备或凭证。fixture 预置明确标记为 synthetic 的 shadow gate 证据，仅用于演示 enforce；生产没有绕过 gate 的参数。

```bash
}

wait_turn "$TURN"

# 3. 仅在 fixture 启用 enforce：连续两次 skipped，modelCalls/toolCalls 都为 0

TURN=$(curl --fail-with-body -X POST "$BASE/api/v1/workspaces/$WS/agent/suppression/wake" \

wait_turn "$TURN"
TURN=$(curl --fail-with-body -X POST "$BASE/api/v1/workspaces/$WS/agent/suppression/wake" \

# 4. kill switch 与强制完整恢复

curl --fail-with-body -X POST "$BASE/api/v1/workspaces/$WS/agent/suppression/reconcile" \

wait_turn "$TURN"
curl --fail-with-body "$BASE/api/v1/workspaces/$WS/agent/suppression/preflight" -H "$AUTH"
```

`docs/runbooks/assistant-suppression.md` 使用同一 API 给出 Source、预算、审计、投影、通知和错误 skip 的恢复步骤及 re-enable 条件。`CHANGELOG.md` 必须记录 additive DDL/API/mode、stateVersion/sourceVersion 兼容矩阵与 off 回滚指南；无破坏性迁移，不需要 codemod。TTHW 分两种记录：依赖就绪后从启动 fixture 到首个正确 wouldSkip 的目标为 2–5 分钟；clean checkout 包含构建的完整时间另行实测，当前均未知。至少一名首次接触该功能的 agent 按文档执行并记录每步时间、命令、实际输出和错误；不能用 warm test 的时间代替 fresh-start 测量。

### 13. Engineering Module Layout

采用较小且隐藏复杂度的结构（全部功能保留）：

```text
apps/cloud/src/domains/agent/session/suppression/
  contract.rs   // versions, canonical bytes, SourceDescriptor/WorkItem/SkipVeto
  registry.rs   // SourceRegistry + conformance entry; six adapters register here only
  preflight.rs  // baseline/cursor/registry comparison -> Decision
  audit.rs      // AtomicSkipAudit + planned-wake idempotency + recovery
  error.rs      // SuppressionError + stable codes + redaction allowlist

apps/cloud/src/domains/agent/session/workspace_api.rs
  // HTTP DTO/auth/problem-details mapping only, no skip business rules

crates/db/src/harness_event.rs
  // existing append behavior + extracted append_session_event_tx helper
```

- `SuppressionService::evaluate` 是 Harness 唯一决策入口；Source 只暴露 capture/resolve。业务语义、版本比较、审计持久化和 HTTP 各自只有一个 owner，内部类型保持 `pub(crate)`。
- 正常 wake 与 reconcile 必须调用同一个现有完整执行函数，仅 preflight 的 `forceFullReason` 不同；禁止复制第二条 Turn/历史/工具路径。
- `append_session_event` 保留现有 event_id/digest 行为，抽取私有 `append_session_event_tx` 供 AtomicSkipAudit 在同一 workspace transaction 中复用。不得另写语义不同的 INSERT；现有 append 回归测试必须保持通过。
- Source 注册表同时驱动 preflight、report 和 conformance，禁止在文档/测试中另维护一份六类 Source 手写清单。
- 备选结构是由 TriggerRouter 直接理解 Source revision 并逐 Source 写入回收状态，拒绝：会把业务语义与调度/存储耦合，并重新引入已延期的 Phase 2。
- 复杂度估计从约 18 个文件/7 个新服务降为约 14 个文件/5 个内聚模块，未裁剪任何功能、错误恢复或测试。模块名与文件数是估计，不是执行配额。

### 14. Overload、超时与背压

- 全局 preflight semaphore 默认同时 4 个（runtime 可配 1..=32），每个 session 仍由 suppression_state CAS 保证至多一个 full/audit attempt。semaphore 饱和时 API 立即返回 429 `wake_backpressure` 与 `retryAfterMs`，不创建无界队列；scheduled wake 按 `(workspaceId, plannedWakeAt)` 合并，恢复后仍能执行。
- 单 Source capture deadline 默认 2 秒、resolve deadline 默认 2 秒、整个 preflight deadline 默认 4 秒，均带 CancellationToken。超时写 `full_failed` 或 `audit_failed` 并禁止 skip；hanging Adapter 不得永久占用 in_flight。正常负载仍以 p95 ≤250ms 为上线目标，deadline 是故障保护而非延迟预算。
- enforce 可启用按 workspace 哈希确定的 0..=15 秒调度 jitter，nextWakeAt=完成时间+interval+jitter；off/shadow 强制 jitter=0，保持现有调度行为，长 Turn 仍按完成时间计算。
- 规范哈希使用增量 writer，不为哈希复制第二份大状态；完整输入若超 provider 预算按既有错误返回。10x/100x 测试覆盖同步爆发、慢/挂起 Adapter、大状态、重放风暴和 SQLite 争用，记录 p50/p95/p99、内存、DB busy/queue、合并比例与背压结果。
- `preflight_timeout` 的 fix 是检查慢 Source 并完整执行，`wake_backpressure` 的 fix 是按 retryAfterMs 使用同一 Idempotency-Key 重试；两者 sideEffects=none、不得推进 baseline，持续发生进入告警。

### Deferred

- Source revision 驱动即时唤醒；首版保留扩展点，不实现。
- 动态延长间隔留待通用无变化抑制上线后验证，不在本设计中实施。

### Success Criteria

1. shadow 模式不改变任何现有模型、工具、历史或回复行为，只增加判定与指标。
2. 固定一组无变化 scheduled Turn，enforce 下连续至少两轮 skip，每次零模型调用、零模型驱动技能/工具执行，并留下完整原子审计。
3. 任一 Source 语义内容变化只需修改该 Source revision/stateHash 就触发完整执行，模型请求仍包含所有 Source 的当前完整内容，Harness 代码不变。
4. 新用户消息使 `seq > controlCursor` 并触发完整执行；cursor 不用于裁剪既有历史。
5. 新增、回答、关闭、直接删除或修改任一工作项会改变其 revision，并在下一轮完整输入中提供当前或最后 payload；payload 不可取得时禁止伪装成健康空集合。
6. 首轮、失败后、取消后、partial 后、上下文拒绝后和损坏/缺失基线后均完整执行，不推进基线/controlCursor。
7. nil/缺失来源、合法空来源、不可用来源和 revision/stateHash 冲突分别测试；任何异常都禁止 skip 并产生可见审计。
8. Source 注册表或 adapter/schema 版本变化使旧基线失效；默认 1800 秒 reconciliation 即使判定无变化也完整执行并注入所有 Source 当前状态。
9. skip 任一事件写入失败后没有可见 skipped 终态，失败屏障保证下一次完整执行；平台 Session 投影失败不被伪装成跨库回滚。
10. 新增一个模拟 Source 不需要修改 Harness，即可验证“无变化 skip → revision 变化完整执行 → 全 Source 当前内容进入输入”。
11. Workspace 快照、Session Events、Turn Brief、Skills、SHORT_TERM.md、长期 Memory 六个首批 Adapter 均通过统一语义符合性测试、真实样本回归和实际注入 smoke test。
12. shadow 达到 3 个代表性工作日、100 个 scheduled Turn 和 wouldSkip ≥50% 后才允许 canary；canary 至少 20 个实际 Turn，实测模型/工具下降 ≥40%、重复报告下降 ≥80%、preflight p95 ≤250ms，并经人工复核无错误 skip 后才允许长期 enforce。没有含样本与审批人的有效 gate artifact 时保持 off/shadow，且不启动 Phase 2。
13. 完整请求超窗或无法计数分别返回 `context_too_large` / `context_budget_unavailable`，不推进状态；接近真实最大开放工作量的负载测试证明人工恢复 runbook 可执行且持续超窗会告警。
14. workspace 开关从 enforce 切到 off 后立即恢复完整执行，无需数据回滚；旧事件与新旧代码并存不会产生可见假 skip。
15. 真实 Session Events Adapter 连续至少两轮 skip 不自反馈；新的外部语义事件仍触发完整执行并进入模型输入，用户事件不双通道消费。
16. Phase 1 代码和任务不包含 analyzedWork、requiredAcks、增量 Source 输入、物理 tombstone 释放或动态调频；这些仅在独立批准后进入 Phase 2。
17. 上线对账发现任一错误 skip 时立即关闭 enforce 并记录事件；保证声明仅覆盖符合契约且已注册的 Source。
18. skip 审计提交后、Schedule 更新前崩溃并重放同一 planned wake 时，只存在一组 skipped 事件；若重放前 Source 或用户输入已变化，则执行完整 Turn。
19. StaticSource 与 ChangingSource 可编译示例通过共享 `assert_source_contract`；payloadHash、stateVersion、registryVersion、规范排序、重复键和所有 ref 规则均有失败测试。
20. 每个新错误路径都验证 code/what/fix/recovery/codeAnchor/context/trace/redaction/channel、sideEffects 与最多 3 次恢复边界；负向测试证明 payload、Memory、秘密和 ref internals 不泄漏。

27. shadow 只产生带分母的 estimated 指标；canary 产生 measured 指标和人工 false-skip 复核。没有包含样本、延迟、审批人与 canary 实测的有效 gate artifact 时不能 enforce。

### System Architecture

```text
assistant_schedules / event wake
              |
              v
      TriggerRouter (existing in_flight)
              |
              v
      WakeRunner / SuppressionPreflight
        |       |          |          |
        |       |          |          +--> existing session_events cursor
        |       |          +-------------> latest successful turn.state baseline
        |       +------------------------> six Source Adapters (batched)
        |                                      |
        |                                      +--> immutable semantic refs
        |
        +--> shadow: existing full Turn unchanged + wouldSkip metrics
        |
        +--> veto/reconcile: existing full history + ALL Source content
        |
        +--> enforce no-change: AtomicSkipAudit (workspace DB transaction)
                                      |
                                      +--> committed events -> SSE -> UI projection
                                      +--> TriggerRouter -> schedule outcome
```

Harness owns versions, preflight, audit and rollback. Source Adapters own business semantics. No device, alarm, energy or skill threshold enters the skip comparator.

### Data Flow and Shadow Paths

```text
Happy: registry + Source refs + user seq
         -> validate available/revision/hash/cursor/reconcile
         -> shadow metric OR atomic skip OR existing full Turn
         -> committed turn facts -> UI

Nil/missing: no baseline/ref
         -> full Turn if constructible, else visible failed Turn
         -> no baseline/cursor advance

Empty: available=true, empty=true, valid revision/hash
         -> valid Source state; may skip only after a successful baseline

Error/conflict: unavailable, revision/hash mismatch, stale registry
         -> degraded full Turn or visible failure
         -> alert + next Turn remains full
```

### Mode and Turn State Machines

```text
off --enable observation--> shadow --shadow artifact--> canary --measured gate--> enforce
 ^                             |                            |
 +-----------------------------+------ kill switch ---------+
 Any false skip or incompatible rollout -> off

scheduled wake
  -> preflight
       -> shadow: full Turn -> successful terminal -> baseline
       -> veto/reconcile: full Turn -> successful terminal -> baseline
       -> canary/enforce no-change: atomic skipped terminal -> baseline unchanged
       -> audit failure: no visible skipped + suppression disabled
```

Invalid transitions are blocked: off/shadow cannot emit a real skip; partial/failed/cancelled cannot create a baseline; enforce cannot bypass reconciliation or launch gates; a duplicate planned wake cannot create a second skipped Turn.

### Async Ordering

```text
Operation A (preflight/skip)     Operation B (source/user change)   Result
capture immutable S              change after S.checkedAt           next Turn sees new revision/seq
compare S to baseline B          complete B's event write           not in S, not covered
commit skip without advancing B  new event persists                 next preflight vetoes skip

Crash after skip commit          same planned wake replay           same event IDs; no duplicate
Crash after skip commit          state changed before replay        discard replay; full Turn
```

Two scheduled/event wakes are serialized by existing workspace `in_flight`. Changes after the pre-turn snapshot are intentionally deferred, never erased by a post-turn baseline.

### Scope Challenge and Structure

Scope accepted as-is with a smaller arrangement, not a scope reduction. The chosen shape hides Source/version/preflight/audit/error contracts inside one suppression module and keeps Source semantics in adapters. The rejected shape makes TriggerRouter understand Sources and reintroduces Phase 2 ownership. Estimated ~14 files/5 cohesive modules replaces ~18 files/7 scattered services without cutting behavior.

Eight red flags checked: canonicalization has one owner; public DTOs parse internal types at the boundary; HTTP is mapping-only; baseline/fences have one DB owner; wake/reconcile share one full-Turn path; append uses one transaction helper; internals are pub(crate); registry drives all six-Source lists.

### Findings and Dispositions

1. **Durable baseline/fences — FIXED.** `suppression_state` marks full attempts in progress before execution, writes full_failed on every unsuccessful terminal, and only a fully successful Turn atomically installs a baseline. Audit/Schedule/projection/notification pending flags are shared across workers.
2. **Replay idempotency — FIXED.** Stable wakeId is separate from monotonic attempt IDs. Changed-state replay creates a linked new attempt; HTTP retries return recorded results and conflicting new intent is rejected.
3. **Gate evidence — FIXED.** Shadow metrics are estimates with formulas and denominators. Canary produces actual measurements and human false-skip review; enforce validates a persisted artifact with samples, measured values, latency and approver.
4. **Canonical Source contract — FIXED.** Shared JCS implementation covers number/Unicode/array edge cases, domain-separated hashes, CanonicalBytes, unavailable error, descriptor validation and golden/property tests.
5. **Commit linearization — FIXED.** Skip commit conditionally checks canary/enforce mode, config/registry generation, user seq and all durable fences. PUT off commits before returning; later external Source changes remain for the next Turn.
6. **Public leakage — FIXED.** Raw turn.state is server-only and filtered by public APIs. Report/preflight/problem DTOs contain approved counts/status/hashes only, never refs, workKeys, revisions, payloads or internal paths.
7. **Overload — FIXED.** Bounded preflight concurrency, capture/resolve/total deadlines, cancellation, wake coalescing, 429 retryAfter and enforce-only jitter are specified. Off/shadow timing is unchanged.
8. **Async API/quickstart — FIXED.** 202 means accepted, final counts live only in report, and every quickstart wake has 40×250ms bounded polling plus curl --fail-with-body.
9. **Configuration contradiction — FIXED.** Recovery means at most three total attempts (initial + two retries, 1s/2s). Reconciliation is configurable with a default of 1800 seconds, not an unconditional 30 minutes.

No production enforce is approved by this document alone. It additionally requires the measured shadow/canary artifacts and the fault-injection tests in the test plan.
