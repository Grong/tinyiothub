# Assistant 错误恢复与可见性

## 目标

当模型 API 或内部临时故障中断 Assistant 时，系统自动重试；前端和历史时间线能看到真实错误、取消来源与每次重试过程。

## 已批准行为

- 网络中断、超时、限流、HTTP 408/429/5xx、流式连接异常和内部临时错误，在同一个模型请求内最多重试 3 次，等待 1、2、4 秒。
- 用户取消、认证/权限失败、无效参数、模型或配置错误及其他不可恢复错误不重试。
- 重试发生在单次模型请求内部，不重启 Turn，不重新执行成功工具，不重复设备写。
- 每次重试持久化 `turn.retry`，包含 `turnId/attempt/maxRetries/delayMs/error`。
- 断流重试时丢弃该次模型请求已经产生的临时正文和思考，避免重试后的内容重复；已提交的工具结果不受影响。
- 最终失败保留真实错误。取消包含可读原因和 `source`，至少区分 `user`、`schedule`、`system`。
- 聊天 SSE 错误字段统一为 `errorMessage`，不再因字段不匹配显示 `Unknown error`。
- 用户主动停止使用 CancellationToken 正常结束 Turn，不再直接 abort 任务而丢失收尾事件。

## 非目标

- 不自动重放失败工具，不绕过重试审批、权限、急停、联锁或 Effect。
- 不恢复已取消的 Turn，不新增固定 Task/媒体配额。
- 不改变 Turn Brief、技能或记忆设计。

## 实现边界

重试属于 rig provider 适配器的单次模型请求；`SessionRunner` 只负责把重试和终态转换为 `session_events`。前端以这些持久事件为真相，同时修复聊天 SSE 的实时错误字段。
